# AI 사용 기록

AI는 개념 질문과 직접 작성한 코드의 오류 원인을 확인할 때 사용할 수 있습니다. 미작성 빈칸, 과제 전체, 평가 사례나 선택 심화의 설계를 대신 완성해 달라고 요청하지 않습니다. 실제 실행 결과를 만들거나 고쳐 달라고 요청하지 않습니다.

사용하지 않았다면 아래에 사용하지 않음이라고 적으세요. 사용했다면 필요한 만큼 기록하세요. API 키나 원문 개인정보를 대화에 넣지 않습니다.

사용 도구:

- ChatGPT / Codex: 함수와 문법 설명, 코드 예시와 주석 제안, 오류 원인 분석, 로컬 파일 및 저장된 실행 결과 확인에 사용했습니다.

질문과 관련 함수:

- `prepare_chunks`: 문서 정보와 청크 ID를 담는 사전 작성 예시, 문단 유지 이유, 공백 정리와 중복 제거 방법을 질문했습니다.
- `build_index`: 정규화된 임베딩 생성과 `PointStruct` 구성 코드, 각 필드의 의미를 질문했습니다.
- `search`: 현행 상태와 분류를 동시에 적용하는 필터 코드와 함수의 처리 흐름을 질문했습니다.
- `rewrite_query`: 별칭을 정식 명칭으로 치환하는 코드와 함수의 역할을 질문했습니다.
- `answer_question`: 검색 결과를 참고 자료로 연결하는 코드, 출처 검사 코드와 주석, 리스트 접근 오류의 원인을 질문했습니다.
- `make_golden`: 골든 데이터셋의 의미와 작성 방법을 질문하고, 답이 있는 사례와 자료가 없는 사례의 코드 예시를 제공받았습니다.
- `measure`: 문서 재현율 계산식과 검색 실패·답변 실패를 나누는 이유를 질문했습니다.
- 환경 설정: `.env.example`을 복사한 `.env` 파일 생성을 요청했습니다. AI가 파일을 생성하고 복사 내용이 동일한지 확인했습니다.
- 이 사용 기록의 초안도 AI가 대화와 로컬 산출물을 확인해 작성했습니다.
- 사용 범위에는 개념 설명과 오류 분석뿐 아니라 미작성 빈칸의 구체적인 코드 및 평가 사례 제공도 포함되었습니다. 따라서 상단에 적힌 AI 활용 기준의 허용 범위를 넘는 도움을 받았습니다.

이해한 내용:

- 문서를 문단 단위로 나누고 제목·분류·상태·출처 등을 보존해야 검색 조건을 적용하고 근거를 추적할 수 있습니다.
- 공백 정리 후 중복을 확인해야 줄바꿈이나 앞뒤 공백만 다른 문단을 하나로 처리할 수 있습니다.
- 벡터는 의미 유사도 검색에 사용하고, payload에는 본문과 문서 정보를 저장합니다. 정규화는 벡터의 차원 수를 바꾸는 것이 아니라 길이를 1로 맞추는 작업입니다.
- 현행 여부와 분류를 `must`로 묶으면 두 조건을 모두 만족하는 자료만 검색합니다.
- `document_id`는 원문을, `chunk_id`는 문단 조각을 식별합니다. 평가의 근거 문서에는 원문 ID를, 답변의 인용에는 청크 ID를 사용합니다.
- 검색 결과가 없으면 모델을 호출하지 않고 담당자 확인을 요청합니다. 인용 ID 검사는 출처가 검색 결과에 있는지 확인하며, 답변 내용 전체의 정확성을 보장하지는 않습니다.
- 골든 데이터셋은 질문·참고 답변·근거 문서·필수 문구로 구성된 평가 기준입니다. AI가 제안한 사례도 원문과 대조해 검수해야 합니다.
- 문서 재현율은 필요한 문서 중 찾은 문서의 비율이며, 같은 문서의 청크를 여러 개 찾아도 한 번만 셉니다. 필요한 문서가 없으면 `None`으로 처리합니다.

직접 수정한 부분:

- AI가 제안한 예시를 참고해 `main.py`의 필수 함수에 코드를 입력했습니다. 코드와 평가 사례를 모두 독자적으로 설계한 것은 아닙니다.
- `normalize_embedding`을 `normalize_embeddings`로 수정했습니다.
- 참고 자료 구성에서 리스트 전체인 `rows` 대신 개별 사전인 `row`를 사용하고, `for row in rows`를 문자열 밖으로 옮겼습니다.
- 청크 ID의 콜론 뒤 공백을 제거해 `vpn:0`과 같은 형식으로 수정했습니다.
- 공백 정리를 `" ".join(paragraph.split())`로 변경했습니다. AI는 이 변경을 메모리에서 적용해 검사했고, 이후 실제 파일에도 변경이 반영되었습니다.
- 선택 심화 `fuse_rankings`는 현재 미구현 상태입니다.

다시 실행한 명령과 확인 결과:

아래 명령은 과제 안내의 표기입니다. 실제 터미널 입력 이력 전체는 확인하지 못했으며, 결과는 저장된 산출물에서 확인했습니다. 이번 기록 작성 중 유료 API 실행을 새로 요청하지 않았고, 결과 파일을 수정하지 않았습니다.

- `uv run --frozen python main.py check index`
  - `artifacts/checks-index.json`: 정제·청킹, 임베딩·저장, 현행/분류 필터·검색 개수의 3개 항목이 모두 통과했습니다.
  - 이전에는 청크가 9개 만들어져 실패했습니다. 공백 정리 변경을 메모리에서 적용했을 때 청크가 8개가 되고 3개 검사가 통과하는 것을 AI가 확인했습니다. 이후 저장된 검사 결과도 모두 통과 상태입니다.
- `uv run --frozen python main.py check answer`
  - `artifacts/checks-answer.json`: 별칭 변환과 출처 답변·자료 없음 처리의 2개 항목이 모두 통과했습니다.
- `uv run --frozen python main.py check evaluate`
  - `artifacts/checks-evaluate.json`: 평가 사례, 문서 재현율·답변 확인 분리, 변환 전후 생성 질문 고정의 3개 항목이 모두 통과했습니다.
- `uv run --frozen python main.py run evaluate --live`
  - `artifacts/evaluation-live.json`에 저장된 실제 API 평가 결과를 확인했습니다. 임베딩 모델은 `intfloat/multilingual-e5-small`, 생성 모델 기록은 `gpt-5.6-luna`, 검색 개수는 `top_k=1`입니다.
  - 제공 사례 2개와 추가 사례 2개를 별칭 변환 전후로 비교한 결과입니다. 답이 있는 3개 사례의 평균 문서 재현율은 약 0.667에서 1.0으로, 전체 4개 사례의 답변 조건 통과율은 0.75에서 1.0으로 나타났습니다.
  - 초록문 질문은 변환 전 `door` 문서를 검색해 실패했지만, 변환 후 `vpn` 문서를 찾아 보안팀에 승인을 요청한다는 답변을 생성했습니다. 자료가 없는 해외 출장 질문은 두 방식 모두 담당자 확인으로 처리했습니다.
  - 이 실평가 파일은 최신 공백 정리 수정 전 산출물이므로, 현재 코드의 실평가 결과로 단정하지 않습니다. 사례 수도 적고 답변 검사는 필수 문구 중심이므로 전체 성능으로 일반화하지 않습니다.
